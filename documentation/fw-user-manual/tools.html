Tools

PC tools

The FOTA wizard, the htn_fw.py command line and fw_release.py, with setup and every command.

Setup

The Python tools live in tools/htn_fota/ and run from their own virtual environment, never from the system Python. They have one dependency, pyserial; the wizard also needs Tk.

sudo apt install python3-venv python3-tk
python3 -m venv tools/htn_fota/.venv
tools/htn_fota/.venv/bin/pip install -r tools/htn_fota/requirements.txt
PY=tools/htn_fota/.venv/bin/python

Your user must be allowed to open serial ports (member of the dialout group). Firmware builds additionally need the ARM toolchain, see Build & flash.

The FOTA wizard

PY tools/htn_fota/fw_wizard.py
  1. Connect FOTA loader. Plug the board that will send the firmware into USB and press Scan USB. Each port is probed and the boards found are listed with type and version. Pick the loader. It can be any tag or anchor running 3.1.0 or newer. A battery powered loader needs at least 30 %.
  2. FOTA loader mode. Press Enable FOTA loader mode. The loader stops its normal work; its status LED blinks fast (on anchors a battery-bar LED).
  3. Choose firmware. Pick a release from the list, or press Open releases folder and drop a htn-fw-anc<ver>-tag<ver>.zip in, then Refresh. Build new release... builds from the working tree and Browse .bin... takes any image file.
  4. Find the target. Press Scan for targets. Every board in UWB range answers with its id, type, firmware and battery; pick one. Boards on 3.1.0 do not answer a scan: type their id and press Connect. A sleeping tag has to be woken first (see wake below).
  5. Flash and verify. Press Start update and wait for Update OK, then Leave FOTA loader mode. The Data rate box can start the transfer slower than the default.

All serial traffic uses 921600 baud. The wizard runs hardware calls on a worker thread, so the window stays responsive during a transfer, and shows progress and a log.

htn_fw.py

--port is the loader board for fota, discover and query, and the board itself for status, flash, led-test, antenna-delay and wake. The default port is /dev/ttyUSB0.

CommandPurpose
statusPrint version, hardware revision, id, errors and (for anchors) link state of the board.
flash <image.bin> [-y]Reflash over the UART bootloader. Works on any firmware version. Asks before leaving a running application unless -y is given.
fota <target> <image.bin> [--rate 6m8|850k|110k] [--kind anchor|tag] [--stay]Use the board on --port as FOTA loader and update UWB target <target>. The kind is detected from the image; --stay keeps the loader in FOTA mode afterwards.
discover [--stay]List FOTA targets in UWB range: id, kind, version, hardware revision, battery, application CRC.
query <target> [--stay]Ask one target for its version and CRC.
fota-exitLeave FOTA loader mode on the board on --port.
led-test [--hold s]Light each LED the firmware can drive, one at a time, to see which are fitted.
antenna-delay [--set TX RX]Read or write the per-device UWB antenna delays (0 or 65535 restores the built-in default). Firmware 3.1.5 or newer.
wake <tag> [--timeout s]Send LoRa wake-up packets through the anchor on --port, one every few seconds, until the tag is heard. The tag then stays awake 15 minutes after the last poll it answers.
selftestOffline checks of the tool itself (frame, CRC, image helpers).
PY tools/htn_fota/htn_fw.py --port /dev/ttyUSB0 status
PY tools/htn_fota/htn_fw.py --port /dev/ttyUSB0 discover
PY tools/htn_fota/htn_fw.py --port /dev/ttyUSB0 query 6
PY tools/htn_fota/htn_fw.py --port /dev/ttyUSB0 fota 6 releases/anchor/3.1.4/Anchor.bin
PY tools/htn_fota/htn_fw.py --port /dev/ttyUSB0 fota-exit
PY tools/htn_fota/htn_fw.py --port /dev/ttyUSB0 flash releases/tag/3.1.3/Tag.bin
PY tools/htn_fota/htn_fw.py --port /dev/ttyUSB1 led-test
PY tools/htn_fota/htn_fw.py --port /dev/ttyUSB1 antenna-delay --set 16550 16500
PY tools/htn_fota/htn_fw.py --port /dev/ttyUSB0 wake 19

The image CRC the tool computes is the STM32 hardware CRC-32 (polynomial 0x04C11DB7, initial value 0xFFFFFFFF, no reflection), fed byte by byte over the image padded with 0xFF to 255 pages (0x1FE000 bytes). That is the value the bootloader checks and the value a target reports as its application CRC.

fw_release.py

CommandPurpose
listShow saved releases with kind, version, size, CRC, build time, git commit and note.
bump anchor|tag [--part patch|minor|major | --set X.Y.Z] [--note ...]Change VERSION in the project's main.h.

importUnpack release zips placed into releases/ (sha256 checked).
ci-check-versionCI only: fail if an image changed but kept an already released VERSION.
ci-publish [--prerelease]CI only: create the GitHub release and its zip from releases/.

The manifest of each release records the version, bootloader CRC, size, sha256, git commit (and whether the tree was dirty), toolchain and date. Tools never contact GitHub on their own; official zips are downloaded by hand and dropped into releases/.

Wire format used by the tools

Every UART message is a frame [opcode, length, payload..., checksum]. The length counts the whole frame and the checksum is the sum of all earlier bytes modulo 256. The UART protocol page has the opcode list.
