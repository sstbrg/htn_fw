Settings

Configuration

Ids, the self-id flash page, antenna delays and crystal trim, backoff, link features and the configuration channel.

Identity

Station id and anchor position

All anchors of a station share one 16-bit station id, stored in slot 0 of the self-id page. Set it with SET_ID (opcode 2). The change takes effect immediately, with no reset: the anchor recomputes its self id and refreshes the ids in its UWB frames and backoff judgement.

The anchor's position in the station (0 to 3, the cable id) comes from two strapping pins read at power-up. Its address on the air is (station id << 2) | cable id. Any anchor with a battery gauge on I2C2 reports its state of charge.

Tag id

The tag id is slot 0 as well; set it with SET_ID on the tag's USB port. A SEARCH_TWR request carries the tag id in the low 15 bits. The LoRa channel of a tag follows from its id (the id modulo the number of 550 kHz channels in the band).

Persistent settings

The page is rewritten as a whole: SET_ID, ANT_DELAY and XTAL_TRIM each read the current page, change their own slots and write it back, so one never erases another. Flash is erased by page, so each change takes a page erase and a write.

Antenna delays (opcode 20)

Antenna delays add a fixed offset to every measured distance; calibrating them against a known distance removes it. Procedure: place tag and anchor at a surveyed distance in line of sight, read the reported distance, adjust and repeat. The DecaWave application note APS014 (in documentation/) describes the method.

PY tools/htn_fota/htn_fw.py --port /dev/ttyUSB1 antenna-delay                 # read
PY tools/htn_fota/htn_fw.py --port /dev/ttyUSB1 antenna-delay --set 16550 16500
PY tools/htn_fota/htn_fw.py --port /dev/ttyUSB1 antenna-delay --set 0 0       # back to the defaults

Anchors send the tag a delay change as a configuration item (LoRa, UWB as backup) so tags can be calibrated without a cable; since tag3.2.0 the response timestamp uses the applied TX delay.

Crystal trim (opcode 23)

The DW1000 crystal can be trimmed from 0 to 31. The saved value is applied at boot and when written; 0xFF clears it, restoring the chip's OTP trim (or mid-range). The reply tells you the saved and the active value.

Anchor settings

Backoff window (opcode 19)

Payload {ctrl, top, min}. The backoff is random() % top + min milliseconds; the bytes are in the old 2.05 ms units (the firmware converts), the defaults are 200 and 10 old units (about 21 to 430 ms). ctrl = 0 turns scan mode off; ctrl = 1 turns it back on (the power-up default is on). Use ctrl = 0 on a bench with several stations when backoffs would only slow measurements down.

A feature switched off makes the anchor ask the tag for maximum power until the tag shows it (the REVERT flag), so switching adaptation off is always safe.

Configuration channel

Some settings reach a tag without a cable: the listen period, antenna delays, crystal trim and, for range profiles, prepare and commit. TAG_CONFIG (opcode 24) queues one item for one tag; the anchor sends it over LoRa and falls back to the extended UWB poll v2 if LoRa has not answered for 3 seconds. After 60 seconds without an answer the item fails. Only one item is in flight at a time.

ItemNameValue
0NOPPing; the answer carries the tag state.
2LISTEN_NListen period 1 to 255 beacons (returns to 20 after 30 s without commands).
3ANT_TXTX antenna delay, 0xFFFF = default.
4ANT_RXRX antenna delay, 0xFFFF = default.
5XTALCrystal trim 0 to 31, 0xFF = clear.
6PROFILE_PREPProfile the tag should get ready for (nothing switches yet).
7PROFILE_COMMITSwitch to the prepared profile after this answer has gone out (0 is always allowed).

The tag listens after a beacon whose counter is a multiple of its listen period: every beacon while UWB is silent, every fourth while extended UWB polls arrive, every twentieth otherwise. Anchors transmit only into windows whose counter is a multiple of four, which all three periods land on. The acknowledgement flags are: rejected (value out of range, nothing changed), LDE NLOS, multi-station (adaptation items held), pending (quieter power request waits for its confirm) and applying (UWB path: taken, applied after this response, the next answer has the read-back).
