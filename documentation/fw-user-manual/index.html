What this repository is

The repository holds the firmware for the HITAN ranging system. A HITAN station is a set of up to four anchors that measure the distance to a tag using DW1000 ultra-wideband (UWB) two-way ranging and receive the tag's status over LoRa. A PC application drives the anchors over USB serial. Three STM32CubeIDE projects build the code that runs on the boards:

ProjectRuns onCurrent versionRole
Anchor/Anchor boardanc4.0.0Ranging initiator, LoRa receiver, UART slave of the PC, FOTA loader and target.
Tag/Tag boardtag3.3.1Ranging responder, LoRa beacon transmitter, battery powered, sleeps when idle.
bootloader_hitan/BothsC3.0.65Lives in flash bank 1, validates the application and accepts a new one over UART.

Quick start

  1. Set up the tools. Install the ARM toolchain and create the Python virtual environment as described in Build & flash and PC tools. Add your user to the dialout group.
  2. Build. From the repository root run tools/build.sh Anchor or tools/build.sh Tag. The images appear in <Project>/Debug/.
  3. Flash. A board that already runs a HITAN image is updated over the air with the wizard, or over USB with htn_fw.py flash. A blank board needs the bootloader first, through an ST-Link.
  4. Check. htn_fw.py --port /dev/ttyUSB0 status prints the version, hardware revision, id and error bits of the board.
Two rules that protect the hardware. Application images are linked at 0x08200000. Flash the .hex (it carries its own addresses); never write an application .bin to 0x08000000, which would overwrite the bootloader. All serial ports run at 921600 baud; a different baud can leave the board's UART deaf until a power cycle.

Conventions used in this manual

  • Commands run from the repository root. PY stands for tools/htn_fota/.venv/bin/python.
  • Multi-byte values on the UART and in UWB/LoRa frames are little-endian. Every structure is packed.
  • Versions are written anc<major>.<minor>.<patch> and tag<major>.<minor>.<patch>. They live in the VERSION define of each project's main.h.
  • Section labels such as 9D or 9J, and issue numbers such as #5 and #7, refer to the design document documentation/HITAN_firmware_changes.html and to the GitHub issues of the repository. The design document is frozen; new requirements go through issues.
