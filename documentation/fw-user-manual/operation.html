How it works

Operation

What a running anchor and tag do: ranging, LoRa, sleep and wake-up, backoff, link adaptation, range profiles and self-recovery.

Main loops

Both applications run a single main loop. The 1 ms timer interrupt (TIM4) gives the tick used for every timeout and drives the software watchdog; the UWB and LoRa radios raise interrupts that set flags the loop consumes.

The tag's loop is the mirror image: it keeps the DW1000 receiver armed to answer polls (dwRange), runs the LoRa beacon machine (Lora_TagService), handles UART frames, upkeeps LEDs and finally decides whether to sleep.

Ranging

Ranging is single-sided two-way ranging (SS-TWR) with clock-offset correction. The PC sends SEARCH_TWR with a tag id. If the anchor is not backing off, UWB is available and the request is not LoRa-only, it runs a range round of one to five exchanges: it sends a poll, the tag answers with the time it received the poll and the time it sent the answer, and the anchor combines them with its own two timestamps. The distance is reported in centimetres as an unsigned 32-bit number. TX and RX antenna delays default to 16550 and 16500 and can be calibrated per device (Configuration).

What the reply tells you

The data_status byte of the reply combines two flags: the UWB part is 0x00 when this round produced a range and 0xF0 when it did not; the LoRa part is 0x00 when a fresh beacon from the requested tag was received since the last reply and 0x0F otherwise. So 0x00 means both are valid, 0xF0 means no range, 0x0F no beacon, 0xFF neither. Flags are consumed by the reply: the UWB flag is reset when the reply is built, and the LoRa fields are zeroed after each reply, so the next reply reports only what arrived in between.

  • Error bits in the reply (errors): no_LoRa, no_UWB (radio failed to initialise), UWB_Backoff (a backoff is running), wrong_UWB_ID (a response came from another tag). The tag's own bits arrive over LoRa as tag_errors.
  • Wrong id: if the last valid beacon does not belong to the tag now requested, the LoRa fields are cleared so values from another tag are never reported.

The optional third payload byte of SEARCH_TWR sets k_max for this round (feature 9F, see Link adaptation); zero lets the anchor decide.

LoRa

  • Beacon. An awake tag transmits a 6-byte beacon about every 0.55 s: message counter, tag id, battery state of charge and error bits, plus a checksum. The anchor retunes to the channel of the requested tag, reports RSSI, SNR and the signal RSSI of the last beacon and the counter.
  • Wake-up. WAKEUP_MODE (opcode 6) makes the anchor transmit one wake-up packet carrying the anchor id and the scrambled tag id. A sleeping tag whose LoRa radio is in receive mode wakes and starts beaconing. The wake-up is repeated by the PC tool until the tag is heard.
  • Commands. Configuration commands and their acknowledgements use inverted IQ, so a normal receiver (every anchor listening for beacons, and all older firmware) never demodulates them. See Configuration.
  • Power. The anchor controls the tag's LoRa TX power under the negotiated rules of link adaptation (down to -9 dBm, up to 22 dBm in 2 dB steps).

Tag sleep and wake-up

  • After power-up the tag stays awake for 6 seconds, then sleeps unless a wake-up arrived.
  • Answering a UWB poll, or hearing a LoRa wake-up or command from an anchor, rewinds the idle timer to 15 minutes. A message from a PC on the UART rewinds it to one hour (lab use).
  • The tag never sleeps while a configuration command window or acknowledgement is in progress (its inverted IQ would leave the sleeping radio deaf to wake-ups), and not while FOTA is active or counting down.
  • Before sleeping the LEDs go off and the LoRa radio is put back to normal IQ in receive mode, so the next wake-up packet is heard. The MCU enters sleep with the UWB and LoRa reset pins held high.
  • All tag builds must keep WITHOUT_WAKEUP disabled (commented out in the source); with it defined a tag never sleeps and never waits for a wake-up.

Backoff between stations

In scan mode the anchor receives for up to 144 ms at a time. A frame of a different station id arms a backoff random() % top + min milliseconds ahead, once per busy period (a running backoff is not extended). The defaults give 21 to 430 ms. The window is changeable with opcode 19 ({ctrl, top, min}, values in the old 2.05 ms units), and ctrl = 0 disables scan mode and releases an armed backoff. Each anchor seeds its random generator from its ids, tick and chip id so anchors that hear the same foreign frame do not pick the same delay.

Built-in test (imposter mode)

BIT_CONTROL (opcode 8) with tag_imposter = 1 turns an anchor into a stand-in tag: it answers UWB polls and sends LoRa beacons with its own id. Another anchor can then range it, which checks both radios of both boards without a real tag. Sending SEARCH_TWR to the imposter, or BIT_CONTROL with 0, ends it.

Link adaptation (section 9)

Rule zero. Anchor and tag must keep ranging in any firmware mix, and every adaptive step fails toward maximum power on the legacy frames. Every feature ships off; with the feature mask clear, frames and replies are byte-identical to anc3.1.5.

The features are switched with SET_LINK_FEATURES (opcode 22), whose payload is the structure LinkCfg_t; a shorter payload sets the leading fields, an empty payload reads the configuration.

How power steps stay safe

  • Louder is immediate, quieter is negotiated. A louder LoRa request takes effect at once. A quieter one goes request, acknowledgement, confirm, proof, repeated up to five polls, and only then applies.
  • No poll from the owner anchor for 1 s (UWB) or 1.5 s (LoRa) returns the tag to maximum; a legacy poll, or polls from two stations, mean maximum at once.
  • UWB never steps below the DW1000 sensitivity (-106 dBm) plus a 10 dB margin. LoRa only steps up when the SNR is below -7 dB.
  • Only one anchor per station owns the LoRa loop (lora_owner); the PC sets it.
  • With two stations on one tag, adaptation freezes (9K).

Range profiles (issue #7)

A range profile changes the UWB data rate and preamble and, for the tag's beacon, the LoRa spreading factor. Channel 2, PRF 64 and code 9 never change, and LoRa commands, acknowledgements and wake-ups stay at SF12 and maximum power.

ProfileNameUWBPreamble / PACBeacon SF
0far (ground)110 kbps2048 / 64SF12
1mid850 kbps1024 / 32SF10

Profile 0 is the ground state: power-up, reset, wake-up, two stations, FOTA and every unilateral revert land there. The PC sets the same profile on every anchor of the station with SET_PROFILE (opcode 25: a sequence number and the profile; a repeated sequence number is ignored). The owner anchor tells the tag to prepare and then to commit (configuration items 6 and 7); the other anchors arm and follow when they miss. While polls alternate between the target and the previous profile, a reply decides the winner. A switch without proof reverts to profile 0.

Inertial sensor

Both boards initialise the BMI088 accelerometer and gyroscope on SPI1; the no_IMU error bit is set when it does not answer. On the anchor, READ_IMU (opcode 26) returns one raw sample with the tick it was taken at: acceleration and angular rate as raw 16-bit counts, the temperature in units of 1/8 degree Celsius, and the configured ranges (3 g and 1000 deg/s). The IMU interrupt pins are inputs since anc4.0.0.

Watchdogs and self-recovery

  • Software watchdog. A counter decremented in the 1 ms timer interrupt is reloaded to 2051 by refresh_WD() at the top of the main loop. If the loop stalls for about 2 seconds with interrupts running, the interrupt resets the chip.
  • Interrupts-off hangs. Error_Handler() resets the chip instead of looping. The timer interrupt has the highest priority; the radio interrupts run below it so the watchdog can preempt a handler stuck waiting on the radio BUSY line.
  • Fault counters. HardFault, MemManage, BusFault, UsageFault, NMI and watchdog events increment counters in the RTC backup registers; they survive resets and the anchor reports them in the status reply (fault_counter).
  • DW1000. dwRecover re-initialises a failed radio at bounded intervals instead of latching no_uwb. dwRadioWatch compares the radio registers once a second with the profile in force and, on a mismatch, re-initialises on profile 0 (anc3.3.1 / tag3.3.1).
  • LoRa. A lost TX or RX interrupt is recovered by the operation's own deadline; an RX error is consumed so a stale flag cannot stick.
  • UART. A line error re-arms the DMA receive and drops the partial frame, so the host only needs to resend.

LEDs in normal operation

  • Power-up. A short LED sweep; then the status LED turns green when UWB and LoRa initialised and the battery gauge reads above zero, red otherwise.
  • Tag. The status LED lights for about 1 second per event; the link LED lights green for about 5 seconds after a successful range; the battery LEDs show the state of charge in quarters for about 3 seconds and blink the last one when the battery is low.
  • Anchor. Battery bar from the gauge, if a battery pack is wired; BIT pass and fail LEDs and a link-up LED on boards that have them. The LED map depends on the hardware revision.
