Concepts

Overview

What the three firmware projects do, how a station ranges a tag, and how the flash is divided between bootloader, application and settings.

The system

HITAN measures distance and bearing between a fixed or mobile station and a tag. Each anchor is a separate board connected to the PC by USB serial. The PC asks every anchor in turn to range the tag; the anchor transmits a UWB poll, the tag answers, and the anchor computes the distance from the timestamps. In parallel the tag broadcasts a small LoRa beacon with its battery level and error flags, which the anchor reports together with the signal strength.

Radios and why there are two

  • UWB (DW1000) carries the ranging exchange. It is accurate to centimetres and runs on channel 2, 64 MHz PRF, preamble code 9, 110 kbps with a 2048 symbol preamble (range profile 0), which gives the longest reach.
  • LoRa (SX126x, up to 22 dBm) carries what UWB should not: waking a sleeping tag, the tag's periodic beacon (battery, error bits, a message counter used to judge link quality) and, since 3.2.0, short configuration commands. The default setting is SF12, 250 kHz, coding rate 4/5, in the 902 to 928 MHz band; an 863 to 870 MHz plan is available by a compile-time define.

The LoRa channel for a tag is derived from its id, so tags are spread over the band: the channel width is 550 kHz and the id is taken modulo the number of channels. An anchor retunes to the channel of the tag it is asked about.

Anchors, stations and ids

  • Every board stores a 16-bit id in the self-id flash page. For an anchor this is the station id (PC_ID); all anchors of one station share it.
  • Each anchor reads its position inside the station (0 to 3) from two strapping pins at power-up (the cable id). The anchor's UWB and LoRa address is (PC_ID << 2) | cable_id.
  • A tag's id is a plain 15-bit number. The top bit of the tag id in a SEARCH_TWR request means "LoRa only, skip UWB".
  • The hardware revision is read from resistor-strapped pins and reported as HW in the status reply. It selects the LED map and which of the two USB serial interfaces (USART3 or USART6) carries the host link.

Several stations on the air

When an anchor is idle it listens for UWB frames (scan mode). A frame addressed to or sent by a different station id arms a random backoff of 21 to 430 ms (window adjustable with opcode 19). While the backoff runs, SEARCH_TWR skips the UWB part and only reports LoRa data, so two stations do not talk over each other. The status reply reports the milliseconds left and the error bit UWB_Backoff.

Memory layout

The U5A5 has two 2 MB flash banks. The bootloader owns the start of bank 1; the application is linked into bank 2. The last page of bank 1 holds the board's persistent settings and the last page of bank 2 holds the application header written by the bootloader.

Never write an application .bin to 0x08000000. The .hex files carry their addresses, so flashing the hex leaves the bootloader untouched. A factory-blank chip needs the bootloader in bank 1 first, or the boot address option byte pointed at 0x08200000.

Bootloader

The bootloader (bootloader_hitan) is deliberately small. It computes the STM32 CRC-32 over 255 pages of bank 2 and compares it with the value in the header page. If the CRC matches and no update was requested, it jumps to the application. Otherwise it waits on the UART for a new image: START_PROG mass-erases bank 2, WRITE_BUFFER writes 128-byte chunks at increasing addresses, and HEADER_FILE stores the CRC, verifies it and starts the application. A bootloader that receives nothing valid for 60 seconds resets and tries again, so a board with a corrupt image keeps cycling until it is reflashed.

The application enters the bootloader on request: UPDATE_FW (opcode 15) answers, writes the update flag to the SRAM word at 0x40036400 and jumps to the loader. The application clears the flag on every normal start, so the flag cannot make a later reset fall into the loader by accident.

What runs in the application

Anchor and tag share the same structure: a CubeMX-generated hardware layer, the DecaWave DW1000 driver with a small platform layer, the Semtech SX126x driver, and a handful of application modules written for HITAN. A main loop services the UART, the UWB state machine and the LoRa state machine; a 1 ms timer interrupt provides the tick and a software watchdog.
