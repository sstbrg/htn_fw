§1  110 kbps data-rate migration

Switches the radio from 850 kbps to 110 kbps for greater RX sensitivity / range. Apply identically on Tag and Anchor — UM Table 21: the receiver must use the same data-rate/SFD config as the transmitter, or ranging stops entirely.

Preamble length: go to 2048, not 1024. UM Table 57 (Recommended preamble lengths): 110 kbps → 2048 or 4096 (850 kbps → 256/512/1024; 1024 is the top of the 850k range, below the 110k floor). For a max-range 110k system use PLEN_2048, which per UM Table 6 requires PAC64. The firmware author already anticipated this — the commented block at anc/inc/dw1000.h:133–144 is exactly DWT_PLEN_2048 / DWT_PAC64 / DWT_BR_110K. A longer preamble adds airtime (drives the timeout values up, below) and slightly lengthens the round-trip — still far under the ~67 ms 32-bit wraparound limit (1B), so it is safe; just keep the reply delays tight.

§3  Rev-D receive deafness — enable GPIO clocks for the external LNA

Leading suspected root cause of the Rev-D long-range failure. dwt_setlnapamode(...|DWT_LNA_ENABLE) configures GPIO6 = EXTRXE to switch in the external RX LNA — but the firmware never calls dwt_enablegpioclocks(), and dwt_setleds() enables only the de-bounce clock (GPDCE), not the GPIO clock (GPCE/GPRN). UM §7.2.39: "the GPIO clocks need to be turned on, before enabling or disabling the GPIO mode or value … by setting GPCE and GPRN in PMSC_CTRL0." If the GPIO write doesn't take effect, EXTRXE never asserts, the Rev-D LNA is bypassed, and the receiver is deaf — exactly matching RX-only, board-specific (Skylab's integrated front-end doesn't depend on EXTRXE).

3A  blocker  Add dwt_enablegpioclocks() after dwt_setlnapamode() — tag/src/dw1000.cpp:113 & anc/src/dw1000.cpp:93

dwt_setlnapamode(DWT_PA_ENABLE | DWT_LNA_ENABLE);
dwt_enablegpioclocks();  // REQUIRED: sets PMSC_CTRL0 GPCE|GPRN so EXTRXE (GPIO6) actually drives the LNA

One line, both files. APS004 §2: GPIO6/EXTRXE "goes high when the DW1000 is in receive mode" and (reference schematic) drives the RX-path RF switch into the LNA. This fix is curative only if Rev-D's LNA is gated by EXTRXE — confirm with §6 before concluding it is firmware-fixable vs a passive RX-front-end (matching/NF) hardware deficit.

Honest caveat: that an un-clocked GPIO_MODE write silently fails is documented in the UM but not independently re-confirmed by us; treat §3 as a high-probability hypothesis to verify on the bench (§6), not a settled fact. TX works at 2 km because the TX external-PA control (EXTPA/EXTTXE) is driven by the digital TX sequencer path, which is why the failure is RX-only.

§7  LDE algorithm tuning — weak-signal first-path detection

Do §3 (RX path) first. LDE operates on signal that already reached the receiver. If Rev-D's LNA isn't switched in, no LDE value recovers a signal that is below the noise floor. Tune LDE after the receiver is actually hearing — to squeeze the last few dB of weak-signal margin, not as the cure for the 400 m failure. Hence experiment, not blocker.

What the firmware runs today (verified): dwt_configure() calls the stock _dwt_configlde(), which writes LDE_CFG1 = LDE_PARAM1 = PEAK_MULTPLIER(0x60) | N_STD_FACTOR(13) = 0x6D (PMULT=3, NTM=13) and LDE_CFG2 = 0x0607 for 64 MHz PRF. The #ifdef NEW_NTM block at anc/src/dw1000.cpp:110–114 is compiled out — and even if enabled it re-writes the same 0x6D, so it is a no-op-in-waiting, not the NLOS tuning its comment implies.

7A  experiment  Lower the LDE first-path threshold (NTM + PMULT) — write after dwt_configure(), e.g. anc/src/dw1000.cpp:110 / tag/src/dw1000.cpp ~118

§8  Multi-station coexistence — UWB backoff (two anchor systems, one tag)

Line numbers in this section reference the anchor source in firmware_code_for_reference/anchor-tag-bootload-backup-23-9-2026.zip (Anchor/Core/…, firmware sC3.0.67), which is the build that carries opcode 19 (BACKOFF_CTRL). Added 2026-10-13.

Goal. Two stations with different PC_ID (e.g. Mob + Fly) range the same tag. The tag answers whichever anchor polls it (tag/…/dw1000.cpp:253 checks only des == SELF_ID, no pc_id filter), so the only shared resource is the air. The anchor already implements a passive listen-before-talk: between UART commands it sits in dwScanMode() (main.cpp:408, gated by BackOFF_CTRL); any frame whose pc_id (src>>2 for anchor frames, des>>2 for tag frames) is foreign arms backoff_timer = now + random()%200 + 10 (dw1000.cpp:201, i.e. 10–209 ms); a SEARCH_TWR that arrives while it is armed skips dwRange() and answers with errors.bit4 = UWB_Backoff (main.cpp:252, uart_communication.c:176). The PC side will treat that bit as "not polled" and yield. The mechanism is sound but as written it starves the second station — §8A.
Starvation (why 8A is a blocker). dw1000.cpp:201 re-arms the timer on every foreign frame. Station A ranging at ~30 Hz puts a foreign frame on the air every ~11 ms at B's anchors; each one pushes B's deadline ≥10 ms further out, so B's backoff never expires (P(random ≤ 11 ms) ≈ 1%). B reports UWB_Backoff forever, never transmits, so A's anchors never hear B and A never yields. Whoever is already running wins permanently — in both directions, after any handover. A passive backoff can only hand the channel over if the waiting side is guaranteed to transmit after a bounded wait (classic CSMA). Fix: arm once per busy period, expire, transmit.
Bench result, firmware sC3.0.69 (2026-10-13, Fly PC id 1 + Mob PC id 11, tag 56).
  • 8B works: opcode 19 = 0 releases an armed backoff at once and the anchor ranges on the next request; re-enabling does not re-arm by itself.
  • Arming works: five rounds of the other station's traffic arm all three anchors.
  • Expiry is broken — blocker: the Status backoff field (now ms left) counts down and stops at 1; the anchor answers every SEARCH_TWR with bit 4 for good (watched 3 s, and indefinitely in earlier runs). One burst of foreign traffic silences a station permanently. Likely an off-by-one in the countdown or in the expiry compare (< vs <=, or a decrement that stops at 1).
  • 8C half done: Status carries ms left; the TWR reply's distance field is still 0 on a backed-off frame, so the PC cannot size its yield.
PC-side workaround in place: an anchor that reports backoff for longer than 250 ms (+0–150 ms jitter) is released with opcode 19 off/on and polled again. Measured, both stations on one tag for 20 s: 42 + 30 valid ranges/s (each alone: 81–89/s), p95 gap 83 / 229 ms; with backoff off: 13 + 10/s, p95 gap 431 / 368 ms, max 3.6 s. Field scenario (one station alone 10 s, the other joins for 20 s, the first stops), both orders: the newcomer's first range after 0.4–1.4 s; while both run 21–48 valid ranges/s each, worst gap 0.7–1.9 s; the station left alone is back to full rate (85–90/s) within the first second. Releasing a whole station at once instead of per anchor measured worse (worst gaps 5–6 s). With expiry fixed, the release becomes the rare §8A bounded wait instead of the normal path, and the fine window of 8D can interleave the stations per exchange, which is what will shorten those overlap gaps.
Bench result, firmware sC3.0.70 (2026-10-14, same rig). Expiry fixed: after a burst of the other station's traffic the Status field read 42–44 ms left, counted down to 0, and the anchor ranged again by +134 ms. TWR reply: carries the backoff bit only, by design (no time field; only Status counts down). That is all the PC needs: it polls every round anyway, so the next reply shows when the backoff has ended. §9  Attributable CIR, per-exchange timing, negotiated TX power (host request, 2026-10-21)

Line numbers in this section reference the current anchor/tag source (Anchor/Core/Src/dw1000.cpp, Anchor/Core/Lora/Src/Lora.cpp, firmware anc3.1.5). Host side: hitan_rust on the same date.

Why. The field failure that matters is close range with no line of sight — a MOB station near the ground, the tag behind bushes or rocks. Both radios misbehave for one reason: a weak direct path and a strong reflected one. LoRa: the receiver sits near compression (above ≈−30 dBm), the level differences between anchors that carry the direction are squashed, and two-ray fading off the ground swings each level ±8 dB within seconds. UWB: the first path is weak against the reflections, the accumulator saturates on the strong path, and the latched diagnostics the host gates on stop describing the leading edge; bearings scatter 12–14° per round at 1 m (bench replay 2026-10-21). What the host can do is bounded by what the anchor reports. Today only dwt_readdiagnostics is latched per valid exchange (dw1000.cpp:355, dwRange); LDE_PPINDX and ACC_MEM are read live over opcode 12 after RX has re-armed, so they belong to whatever frame came next — the host withholds prNlos for that reason. Measured on the truth-labelled recordings (examples/nlos_features.rs): the three latched first-path taps carry no NLOS information (AUC 0.46); RX−FP is the only discriminator and it is weak (AUC 0.62–0.76).
Rule zero for everything in §9: the link is never lost. Losing communication with the tag is the one failure that is not allowed; every adaptive change below is built so that the worst case of a bad decision, a missed frame or a crash mid-negotiation is a few hundred milliseconds on the robust profile — never a tag that cannot be reached.
  • Control plane stays robust, always. The anchor→tag LoRa command path (wake-up, poll, profile and power requests) is fixed at maximum power and the robust spreading factor, and the tag's LoRa receiver stays on that configuration. Only the tag's beacon and the UWB exchange adapt. LoRa and UWB are separate radios on both sides, so the LoRa control channel is a permanent back door: any state can be undone from it.
  • Profile 0 is the ground state. Any doubt on either side → profile 0, unilaterally and at once. Tag: no frame from any anchor for 1 s. Anchor: two consecutive polls unanswered. Power-up, reset and watchdog restart land on profile 0. Wake-ups always go at profile 0.
  • Make-before-break. A move to a less robust profile or a lower power needs the tag's echo of the request and the anchor's confirmation of that echo (three frames) before either side switches, and two consecutive frames with the level inside the target band after the switch before the next step. A move to a more robust profile or higher power takes effect immediately and without confirmation.
  • Rate-limited and bounded. At most one step every 2 s away from robustness; no limit toward it. Power never below the level that leaves 10 dB of margin over the receiver's sensitivity at the current range, measured at the anchor, not predicted.
  • Channel changes are opt-in and proven first. Shipping builds keep UWB channel 4 disabled until the bench shows ≥ 80 % valid exchanges at 10 m with the installed antennas; even then the near profile falls back to channel 2 after one missed exchange.
  • Chaos test, before any of §9D/9H ships. 100 trials each of: walk the tag away at a run during a step down; cover the tag's antennas by hand; power-cycle one anchor mid-negotiation; power-cycle the tag; two stations on one tag. Pass criterion: the tag is reachable again within 1 s in every trial, zero cases of permanent loss. One failure blocks the release.

  • Retries. The anchor repeats a request on every poll until acknowledged, up to 5 polls; then it cancels (the tag never switched, nothing to undo). The anchor repeats the confirm until the first frame arrives on the new settings, up to 5 polls; then both sides revert (next bullet).

Both reverts are unilateral and need no frame, because the failure case is exactly that no frame gets through.
  • Listen rotation (one radio per side). The DW1000 holds one configuration at a time, so during a transition the anchor alternates its receiver between the new and the old configuration poll by poll until proof arrives, and the tag, when idle, alternates between its current profile and profile 0 every 200 ms. A tag on any profile is therefore always reachable on profile 0 within 200 ms, and the LoRa command path reaches it at any time regardless.
  • Two radios, one truth. A request or confirm is valid if it arrives on either radio; the tag acknowledges on both. Losing one radio never stalls the handshake, and the LoRa path alone can always drive the tag back to profile 0 at maximum power.
  • Two stations, one tag. Requests carry the station's PC id; the tag follows the most recent confirmed request and tells both stations its current settings in every frame. A station whose requested settings are not what the tag reports simply adapts its receiver to what the tag reports (the tag's settings are authoritative), and does not fight: it never requests a less robust profile than the other station's last confirmed one.
  • Hard rule for the implementation: there is no code path on either side that changes a radio setting without a confirmed sequence number, except the reverts toward profile 0. A watchdog on each side asserts, once per second, that the configured radio matches the last confirmed state or profile 0; any other state is reset to profile 0.

9K  Two stations, one tag: adaptation is frozen, backoff untouched required

Backoff already costs performance today (§8: 42 + 30 valid ranges/s with two stations against 81–89/s alone, p95 gaps of 83 / 229 ms). Nothing in §9 may make that worse, and nothing in §9 may add a second mechanism that interacts with it. So the rule is not "coordinate the two", it is "do not adapt while there are two".
  • Two stations ⇒ ground state. While the tag has heard polls from more than one PC id in the last 2 s, it reports that, and every adaptive feature is off on both sides: profile 0, maximum power, K = 1, no requests sent, no handshake in flight. A station whose anchors have backoff armed, or that reads "two stations" from the tag, likewise sends nothing but profile 0. The §8 backoff, yields, duty cycle and release logic then run exactly as they do now, on the configuration they were tuned on.
  • Entering coexistence. If a second station appears while the tag is on a near profile at low power, the tag reverts to profile 0 at maximum power by itself (rule zero's unilateral revert, within one listen-rotation period) and the first station follows the tag's reported settings. The newcomer always polls on profile 0 and so reaches the tag within 200 ms; it never has to know what the tag was doing before.
  • Leaving coexistence. Adaptation may resume only after the tag has reported a single station for 2 s and no anchor of that station has backoff armed. The first step away from profile 0 is then one ordinary 9J handshake.
  • Anchor-local features that do not touch the air — 9G LDE preset, the 9A/9C reply bytes, the 9B CIR latch — stay on with two stations. 9F repeats do touch the air and are forced to K = 1.
  • The fixed duty cycle stays as tuned. While sharing the tag the host takes turns on fixed ON/OFF slots and releases a backed-off anchor after ON + 250 ms (§8, host side). Those timings assume one exchange per poll on profile 0; the freeze keeps that true, so the slots, the release margin and the yield are not recomputed for §9 and never need to be. The tag's silence timers (500 ms revert to the previous settings, 1 s to profile 0) must be longer than the longest configurable OFF slot plus the release margin, so a station's own pause can never look like a lost link to the tag; with two stations the tag is on profile 0 anyway, and a lone station never pauses, so duty cycling and adaptation never run at the same time. The only overlap is the hand-over, and it passes through the ground state.
  • Per-station sequence numbers (9J) remain, so a stale request from a station that has just gone quiet cannot be mistaken for a live one.
  • Regression gate. Every §9 feature ships only if the §8 two-station bench (both orders of joining, 20 s overlap, one station alone 10 s before and after) shows valid ranges per second and p95 gaps no worse than the sC3.0.70 figures, with the feature enabled on both stations. A feature that costs two-station throughput is kept off until it is fixed, whatever it buys alone.

9L  Antenna-delay calibration — routine for the analyzer important

Absolute range accuracy rests on the antenna delays (APS014: ≈30 cm 3σ uncalibrated, 2.15 mm/°C drift). Since tag3.2.0 both the TX and the RX delay count. Before that only the tag's RX delay did, so every tag calibrated earlier must be redone.

Firmware support today:

  • Opcode 20 ANT_DELAY: {tx u16, rx u16} in DW time units (15.65 ps); 0 or 0xFFFF = back to the default (anchor 16550/16500, tag 16500/16500); empty = read. Reply {status, tx, rx} with the flash values. Applied at once and kept across resets, firmware updates and SET_ID. Over UART, one device at a time.
  • Opcode 8 BIT_CONTROL {tag_imposter = 1}: turns an anchor into a responder, so anchors can range each other. The imposter now uses its own flash delays in its response.
  • Sensitivity: each unit of TX or RX delay on either device moves the range by 2.346 mm; more delay reads shorter. Measured: +100 tag TX units → −24.0 cm.

Procedure (three-device method, APS014):

  1. Setup. Line of sight, devices on stands ≥ 1.5 m high, antennas facing, 10–30 m apart, distances measured to ±1 cm. Too close and the APS011 level bias skews the result, and the chip cannot report it. Keep the analyzer's rx level at or below ≈−85 dBm, or increase the distance. Features off (opcode 22 = 0: LOS LDE, K = 1), all delays at the default. Note the temperature.
  2. Anchor triangle. Take three anchors A, B, C at known distances dAB, dAC, dBC. For each pair, put one anchor in imposter mode and range it from the other with ≥ 200 valid exchanges; take the median. Do both directions and average them. Error per pair: eij = medianij − dij.
  3. Solve. Range error per device: EA = (eAB + eAC − eBC)/2, EB = (eAB + eBC − eAC)/2, EC = (eAC + eBC − eAB)/2. Delay change per device: Δ = E / 2.346 mm units in total, split evenly: TX += Δ/2 and RX += Δ/2. Write them with opcode 20.
  4. Iterate once. Re-measure the three pairs; the residual should be under 2 cm. Repeat step 3 on the residuals if not.
  5. Other anchors. Range each one (as imposter) from a calibrated anchor. The whole error E = median − d belongs to the new anchor.
  6. Tags. Range each tag at a known distance from a calibrated anchor (preferably two anchors; average them). Etag = median − d → TX/RX += E/(2 × 2.346 mm) on the tag: opcode 20 over USB, or opcode 24 (items 3/4) over the air.
  7. Accept. |median − d| < 2 cm at the calibration distance and < 5 cm at a second distance. Store the per-device values with date, temperature and firmware version in the analyzer.

Over the air (implemented, 9J): the analyzer can push the values to a tag in place, at the calibration distance, without a cable. Send opcode 24 to any anchor of the station: item 3 for the TX delay, 4 for the RX delay, 0xFFFF for the default. Poll opcode 24 until state = 2 and check the read-back. LoRa delivers it, and the UWB backup takes over after 3 s. Step 6 then runs without a cable; anchors are still set over their UART (opcode 20).
