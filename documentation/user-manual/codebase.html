How the source is organized

A workspace map and file-by-file guide to the Rust source, for engineers taking ownership of the project.

Workspace at a glance

hitan-analyzer

Native egui desktop application: screens, state, recordings and background workers.

hitan-core

Shared device protocol, serial transport, logging, diagnostics and ranging math.

hitan-cli

Terminal menu for direct device operations using the same core library.

Trace a feature through the system

  1. Transport: hitan_core::serial_bus sends serialized transactions; protocol frames and parses bytes; Device exposes hardware operations.
  2. Background I/O: analyzer workers own devices while sampling and send results through channels so radio calls do not block the UI.
  3. UI state: app/update.rs drains channels and dispatches rendering to LOCATE or an Advanced tab.
  4. Analysis: core contains reusable quality gates and solvers; the analyzer trilateration pipeline adds application filtering and presentation data shared by live and playback.
  5. Persistence: core sample_log handles the .hpb stream format; analyzer recording/loading modules handle filenames, UI state and playback.
Good first files: start with crates/hitan-analyzer/src/main.rs, then app.rs and app/update.rs. For a screen, follow its renderer in tabs/ or locate/. For hardware behavior, trace hitan-core/src/device.rs down to protocol and serial transport.

Build and data files outside src/

  • Root Cargo.toml defines the workspace; each crate has its own manifest.
  • crates/hitan-analyzer/build.rs stamps build metadata. crates/hitan-core/build.rs generates protobuf Rust code.
  • crates/hitan-core/hitan_sample.proto defines persisted TWR/trilateration records. Keep schema changes compatible with existing .hpb files.
  • deploy/ contains Ubuntu packaging/install scripts. documentation/ contains this manual and radio references.

Maintainer notes

  • Trace a vertical slice before editing: screen → app state/update → worker/core API → protocol/transport.
  • Keep blocking serial I/O off the egui thread.
  • For recording features, check writer, loader and playback paths; TWR and trilateration records share an extension but have different message types.
  • Protocol and numerical changes should preserve hardware and file-format compatibility. Read neighboring tests/fixtures before changing those contracts.
  • See the repository README.md for build commands, workspace overview and performance constraints.
