Migration to 110 kbps Two-Way Ranging

Line-exact changelist for the Tag and Anchor firmware, grounded in the Decawave reference driver and DW1000 User Manual.

Target: 850 kbps → 110 kbps Radio (unchanged): Ch 2 · PRF 64M · PLEN 1024 · code 9 Scheme: Single-sided TWR Date: 2026-06-09
Why ranging breaks at 110 kbps today. The anchor computes clockOffsetRatio with FREQ_OFFSET_MULTIPLIER (the 1024-sample constant). At 110 kbps the carrier integrator accumulates over 8192 samples, so the raw value is 8× larger — the correction is over-applied, (1 − clockOffsetRatio) swings negative, rtd_resp > rtd_init, and the time-of-flight goes negative. Removing abs() exposes the symptom; fixing the multiplier (change A5) is the actual cure.

File 2 — Anchor code anc/src/dw1000.cpp

A5  blocker  Data-rate-aware carrier-integrator multiplier  (lines 296–298 — the root-cause fix)

/* was: uses the 1024-sample constant unconditionally */
double freqOffsetMultiplier =
        (config.dataRate == DWT_BR_110K) ? FREQ_OFFSET_MULTIPLIER_110KB
                                         : FREQ_OFFSET_MULTIPLIER;
clockOffsetRatio = dwt_readcarrierintegrator()
        * (freqOffsetMultiplier * HERTZ_TO_PPM_MULTIPLIER_CHAN_2 / 1.0e6);

config is the file-static dwt_config_t from the header and is in scope here. 850k and 6.8M correctly fall through to the 1024 constant — which is why 850k works today.

A6  blocker  Validity guard instead of abs()  (lines 309–312)

After A5 the value is physical, but at 110k you sit closer to the 32-bit timestamp wraparound ceiling (~67 ms). A negative result now means a bad sample — reject it rather than fold it into a fake short range.

double tof = ((rtd_init - rtd_resp) / 2.0) * DWT_TIME_UNITS;
if (tof < 0) {                          // non-physical: clock/wraparound glitch
    dwmInfo.dw_ready = DW_NO_VALID_DATA;     // drop the sample
} else {
    dwmInfo.tof      = tof;
    dwmInfo.distance = dwmInfo.tof * SPEED_OF_LIGHT * 100;
    dwmInfo.dw_ready = VALID_DATA;
    dwt_readdiagnostics(&dwmInfo.diagnostics);
    dwmInfo.wrong_ID = false;
}

Minimal alternative: simply restore abs(). Once A5 is in, abs() only fires on rare wraparound and no longer masks a calibration bug — but the guard above is better because it discards the glitch instead of reporting a wrong distance.

No change at lines 118–119 (dwt_setrxaftertxdelay/dwt_setrxtimeout) beyond A3 — they already read the macros. dwt_configure() (line 98) auto-applies SYS_CFG_RXM110K, LDE_REPC÷8, DRX_TUNE0b, DRX_TUNE1b_110K from the enum.
